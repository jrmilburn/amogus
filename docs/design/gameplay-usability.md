# Desktop and mobile gameplay usability

Impeccable source assessment, 2026-09-06. Two independent assessments covered gameplay navigation, action controls and all eight task instruments. Both prioritized the same five fixes below. The existing station palette and instrument designs are retained.

| Playing friction                                                                                              | Implemented fix                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Phones show E/Q/V and keyboard instructions; shortcut badges also carry important cooldown/count information. | Instructions and accessible labels follow touch or keyboard input. Shortcut badges hide on touch, while cooldowns, meeting counts and action names remain. The keypad uses **Submit** and tasks have a labelled **Close** button.                                                                                                                                                                                        |
| Contextual actions disappear and move the remaining buttons under the player's thumb.                         | Fixed 64px action positions: Use bottom-right, Kill beside it, Vent/Repair above, Sabotage/Meeting above those. Report replaces Meeting in the same slot when a body is available. Use keeps its position when unavailable and names the nearby task. Vent routes open beside the dock.                                                                                                                                  |
| Equipment looks similar, and the task indicator appears only once the player reaches use range.               | Consistent private diamonds identify unfinished assigned stations in visible world space and on the map. Mint marks tasks, white identifies the tracked task, and amber with a centre dot indicates the nearby station is ready to Use. Markers follow task stages and respect visibility and comms disruption. Visibility is filtered before selecting the nearest station so an unseen station cannot steal targeting. |
| Focusing Tasks or Map prevents WASD movement, including after the normal task-close focus restoration.        | WASD works from passive HUD controls. Arrows retain native panel scrolling, and typing, task dialogs and vent routes protect their input. Entering a text field clears held movement.                                                                                                                                                                                                                                    |
| Tall sample and keypad tasks require excessive scrolling on short landscape screens.                          | At landscape widths of at least 600px and heights up to 500px, guidance/status sit beside the instrument, sample columns become two-column racks, and the code display sits beside the keypad. Close stays in a sticky header. Instrument targets remain at least 48px; smaller portrait screens retain a single column.                                                                                                 |

## Verification

- The post-change Impeccable scan of changed UI markup returned zero findings. The baseline source scan reported one intentional vial-cap border warning in `minigames.css`; this is an instrument shape, not a new panel treatment.

No browser overlay server or temporary browser assets were created. The two assessments were independent until synthesis; there is no measured post-change usability score.
