# Minigames, batch B — #12

Impeccable extends the incumbent station modal with four code-native instruments: a filling/emptying amber canister, a ribbed duct containing five labelled debris pieces, a five-digit memory display with a native keypad, and an engineer pass sliding through a reader. The small controls are at least 48px high; art uses existing station colours, readable labels and explicit feedback rather than colour alone. The CSS ribs describe a duct, not a decorative page grid.

- **Fuel engines:** accumulate five seconds of held pump time per station. Release, pointer cancellation and blur stop the pump. Progress within the open attempt pauses on release; closing discards that attempt. A completed fill stage remains saved while walking to the engine and retrying emptying.
- **Clear vents:** drag each piece outside the duct boundary. Captured pointer movement follows the piece, and an inside drop returns it without credit. Select-then-Remove supports touch and keyboard without dragging; duplicates cannot count twice.
- **Access code:** explicitly reveal a random five-digit code for two active seconds (leading zeros retained), then use the keypad or keyboard digits/Backspace/Enter. Reveal again clears the entry and retries the same local code. A wrong answer never completes the task. The reveal is repeatable for accessibility; its screen-reader and two-second readability acceptance is still pending.
- **Scan ID:** drag from the left to at least 95% of the reader in 800–1600ms without reversing more than an 8% tolerance. Incomplete/fast/slow/reversed attempts reset with specific feedback. Hold-to-swipe moves the pass in about one second and evaluates the same timing model on release, providing a keyboard alternative. Blur/cancel discards the attempt.

The existing `StationGame` lifecycle, active clock, minimum-duration confirmation, sound hooks, private sessions and modal cancellation are reused. `minigames/factory.ts` dispatches all eight mapped types; the old HoldTask is only a defensive unknown-type fallback. Server minima are five seconds for every non-data task; quick successful ID/code attempts wait for the station procedure floor before submitting. Audio remains #19. Client puzzle actions are not independently server-verified; assignment, location, stage, role, timing and aggregate progress are authoritative.
